# 08. Нефункциональные требования, тестирование, приёмка

## 8.1. Устройства и тиры

| Тир | iOS | Android | ОЗУ | Эталонные устройства для тестов |
|---|---|---|---|---|
| **A** | iPhone 13 и новее (A15+) | Snapdragon 8 Gen 1+, Dimensity 9000+, Tensor G2+ | ≥ 6 ГБ | iPhone 15, Samsung Galaxy S23 |
| **B** | iPhone XS/XR, 11, 12, SE 2/3 (A12–A14) | Snapdragon 7-й серии (778G, 7 Gen 1+), Dimensity 7000-й серии, Exynos 1280/1380 | 4–6 ГБ | iPhone 11, Samsung Galaxy A54, Google Pixel 6a |
| **C** | iPhone 8/X (A11) | Helio G85/G99, Snapdragon 680/695 и аналоги | 3–4 ГБ | Samsung Galaxy A15, Xiaomi Redmi 13C |

**Минимальные требования:** iOS 16; Android 8.0 (API 26); ARM64; OpenGL ES 3.1 или Vulkan 1.1; 3 ГБ ОЗУ. Устройства ниже минимума исключаются в Google Play по ОЗУ и характеристикам (device catalog); iOS — минимальной версией ОС (вопрос В15).

**Определение тира** — по таблице известных SoC/GPU (обновляется через Remote Config) и, для неизвестных устройств, по микробенчмарку при первом запуске (≈ 2 с: физика 500 тел + заполнение экрана), результат кэшируется. Пользователь может вручную выбрать «Экономное» или «Высокое» качество в настройках.

## 8.5. Стратегия тестирования

| Уровень | Что | Где | Когда |
|---|---|---|---|
| Модульные тесты ядра | Параметры и схемы, пресеты, миграции проектов («золотые» файлы), права — полный перебор 2¹⁵ сочетаний товаров, рекламные правила (сценарные тесты конечного автомата IN1–IN8, RW1–RW7), оценка зрелищности, формат `.bvr`/`.bvs` (запись → чтение), математика таймлайна | `dotnet test`, любой контейнер | каждый коммит |
| Детерминизм | Для каждого режима: 20 сидов × 2 прогона → совпадение всех хэшей; пересчёт потока рендера из реплея → совпадение хэшей | Unity batchmode (EditMode) | каждый PR |
| Качество генерации | 200 сидов на режим: доля кандидатов выше порога, попадание в целевую длительность, отсутствие «застреваний» | Unity batchmode, `tools/balance-probe` | ночная сборка |
| Баланс | M06: 10 000 headless-боёв → шанс победы каждого бойца 1/N ± 5% | `tools/balance-probe` | при изменении оружия |
| «Золотые кадры» | Рендер заданного тика заданного реплея в 1080×1920 → сравнение с эталоном (SSIM ≥ 0,99) | раннер с GPU или устройство | каждый PR, затрагивающий Render/Studio |
| Компоновщик студии | 5 раскладок × «поменять местами» × 2 разрешения: предпросмотр против экспорта (SSIM ≥ 0,98) | устройство | перед релизом |
| Экспорт | Оверлей кадрового счётчика → экспорт → декодирование файла → проверка последовательности 0…N−1 без пропусков и повторов; свойства файла (`ffprobe`); загрузка в TikTok/Shorts/Reels вручную | эталонные устройства | каждый релиз-кандидат |
| Нативные модули | XCTest (iOS), JUnit + инструментальные тесты (Android) на реальных кодеках; матрица входных видео: H.264/HEVC, 24/30/60/120 FPS, VFR, повороты, HDR (Dolby Vision, HLG), без звука, 4K | Firebase Test Lab (реальные Android-устройства), устройства iOS | ночная сборка / релиз |
| Производительность | Сцены-бенчмарки на каждый режим с максимальным бюджетом тел; p50/p95 времени кадра, время экспорта, память; регрессия > 10% — блокер | эталонные устройства (Firebase Test Lab game loop для Android, TestFlight-сборка с бенчмарком для iOS) | еженедельно и перед релизом |
| Покупки | StoreKit Configuration File (локально), Sandbox, лицензионные тестеры Google; сценарии: покупка, отмена, ожидание, восстановление, возврат, смена устройства, «умная витрина» | устройства | перед релизом |
| Реклама | В отладочных сборках — только тестовые рекламные блоки (проверка в CI: релизная сборка содержит боевые ID, отладочная — тестовые); UMP с тестовой геолокацией ЕЭЗ | устройства | перед релизом |
| Ручной регресс | Чек-лист §8.6 на 8+ устройствах: 3 iOS (тиры A, B, C) и 5 Android (Samsung, Xiaomi, Pixel, бюджетный MediaTek, планшет как совместимость) | QA / владелец | каждый релиз-кандидат |

## 8.6. Чек-листы приёмки

### Готовность функции (Definition of Done)

1. Реализована по разделу ТЗ, критерии приёмки раздела выполнены.
2. Модульные тесты ядра и тест детерминизма (для режима) проходят в CI.
3. Нет новых предупреждений анализаторов; нет строк вне таблиц локализации.
4. Работает на эталонных устройствах тиров A, B, C в пределах бюджетов §8.2.
5. Аналитические события функции отправляются (§9.2) и проверены в DebugView Firebase.
6. Обновлены `docs/dev/` (журнал) и, если менялось поведение, это ТЗ.

### Зрелищность режима (проверяет владелец)

Для каждого режима — 20 генераций подряд с настройками по умолчанию:

- [ ] Ни одной «скучной» генерации (нет отрезков > 3 с без событий; финал читается).
- [ ] Звук приятный на пакетах `Notes` и `Melody`, нет «каши» при массовых ударах.
- [ ] Результат понятен без подписей (кто победил, что произошло).
- [ ] Ролик 15–30 с из этого режима хочется досмотреть до конца.
- [ ] Цвета темы `Neon` и `Pastel` выглядят дорого; нет мерцания и «рваных» краёв.

### Релиз-кандидат

- [ ] Все 15 режимов: запуск, генерация, пресеты, режиссёр (где есть), «В видео».
- [ ] Студия: импорт (5 типов файлов из матрицы), 5 раскладок, текст, звук, предпросмотр.
- [ ] Экспорт: 720p30, 720p60, 1080p30, 1080p60; загрузка в TikTok, Shorts, Reels.
- [ ] Прерывания: звонок, уход в фон, блокировка экрана, нехватка места, авиарежим, выгрузка системой во время экспорта.
- [ ] Монетизация: все 15 товаров, восстановление, «умная витрина», водяной знак (без права — всегда есть; Ultimate или полный состав по частям — снимается; возврат покупки — возвращается), rewarded-шлюз (включая «реклама не загрузилась»), interstitial по правилам IN1–IN8, отключение рекламы покупками.
- [ ] Согласие: UMP (ЕЭЗ), ATT, отказ от всего — приложение работает.
- [ ] Локализация EN/RU: ни одной обрезанной строки на самом узком устройстве.
- [ ] Доступность: «Без резких вспышек», «Уменьшить движение», «Уменьшить прозрачность», крупный текст.
- [ ] Метрики §8.2–8.4 в пределах целей на эталонных устройствах.

## 8.9. Безопасность и приватность

- В клиенте нет секретов, кроме публичных ключей конфигурации (Firebase, AdMob App ID).
- Данные приложения — только в песочнице. Видео пользователя никогда не отправляются в сеть.
- Сетевые запросы — только SDK (Firebase, реклама, магазины), только HTTPS.
- IL2CPP + удаление неиспользуемого кода; дополнительная обфускация не требуется (нет серверной логики, которую нужно защищать).
- Отладочное меню и тестовые рекламные ID физически отсутствуют в релизной сборке (символы компиляции, проверка в CI).
