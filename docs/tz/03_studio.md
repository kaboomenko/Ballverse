# 03. Студия: запись, видеоредактор, предпросмотр, экспорт, проекты

Студия (`Studio`) — встроенный видеоредактор Ballverse. Его задача — не конкурировать с CapCut, а за 1–2 минуты превратить клип симуляции и (необязательно) видео пользователя в готовый вертикальный ролик.

Главный технический принцип студии: **предпросмотр и экспорт рисуются одним и тем же компоновщиком кадра** (§7.5). Что пользователь видит в предпросмотре, то и получит в файле: те же раскладки, шрифты, отступы, эффекты.

## 3.1. Запись игрового процесса (Требование 4)

### Модель записи

- Каждый запуск симуляции автоматически пишется как **реплей** (§1.3, §7.4). Это не видеозапись экрана, а данные, из которых кадры восстанавливаются в любом разрешении.
- После финала (или в любой момент паузы) доступна кнопка **«В видео»**. Она превращает текущий реплей в **клип** и открывает студию.
- Кнопка **«Сохранить клип»** кладёт клип в библиотеку клипов без открытия студии (для тех, кто набирает материал впрок).
- Несохранённые реплеи хранятся в кольцевом буфере последних **5 запусков** (на случай «ой, предыдущий был лучше»). Экран результата содержит «Предыдущие запуски» — горизонтальную ленту из 5 миниатюр.

### Почему не запись экрана

| Критерий | Запись экрана (ReplayKit / MediaProjection) | Реплей + офлайн-рендер (выбрано) |
|---|---|---|
| Плавность итогового видео | зависит от FPS устройства, рывки на слабых | всегда ровно 30/60 FPS |
| Разрешение | равно экрану | 720p/1080p независимо от экрана |
| Интерфейс в кадре | попадает, нужно прятать | не попадает никогда |
| Нагрузка во время игры | кодирование в реальном времени греет телефон | почти нулевая (килобайты данных) |
| Разрешения системы | нужен системный диалог записи | не нужны |
| Качество графики | равно настройкам реального времени | в экспорте можно включить максимум (§7.7) |
| «Записать задним числом» | невозможно | любой из последних 5 запусков |
| Сложность | низкая | высокая: детерминизм, офлайн-рендер (§7.4–7.5) |

### Приёмка

- Любой завершённый запуск можно отправить в студию одной кнопкой, без повторного запуска.
- Экспорт клипа покадрово совпадает с тем, что пользователь видел на экране (сверка позиций тел в контрольных тиках, §8.5).
- Реплей без потока рендера весит ≤ 200 КБ на минуту для всех режимов, кроме M09 и M15 (≤ 1 МБ).

## 3.2. Импорт видео из галереи (Требование 5)

| Аспект | iOS | Android |
|---|---|---|
| Системный выбор | `PHPickerViewController` (без запроса доступа ко всей галерее) | Photo Picker (`ActivityResultContracts.PickVisualMedia`), на старых версиях — бэкпорт через Google Play services |
| Разрешения | не требуются | не требуются |
| Копирование | Файл копируется в папку проекта в песочнице приложения (с прогрессом) | То же |

### Требования к входному видео

| Параметр | Поддержка |
|---|---|
| Контейнеры | MP4, MOV (iOS), MP4/3GP/WebM (Android — что поддерживает системный декодер) |
| Кодеки | H.264, HEVC; VP9/AV1 — если есть аппаратный декодер, иначе понятная ошибка |
| Разрешение | до 4K; при импорте ничего не пережимается, масштабирование при компоновке |
| Частота кадров | любая (24–120); при экспорте пересэмплируется к 30/60 по ближайшему кадру |
| Ориентация | учитывается матрица поворота (видео с телефона «на боку») |
| HDR (Dolby Vision, HLG, HDR10) | **Тонмаппинг в SDR BT.709** при декодировании. Экспорт всегда SDR (§10, риск R7) |
| Длительность | до 10 мин на входе; в ролик попадает фрагмент ≤ 180 с |
| Переменная частота кадров (VFR) | поддерживается, кадры выбираются по меткам времени |
| Звук | AAC, MP3, Opus (если поддерживается системой); моно/стерео |
| Без звуковой дорожки | поддерживается |

- При импорте показываются длительность, разрешение и предупреждение, если файл занимает > 25% свободного места.
- Видео из iCloud, которое ещё не загружено на устройство, загружается с прогрессом и возможностью отмены.
- Ошибки импорта (неподдерживаемый кодек, повреждённый файл, DRM) — понятным текстом с вариантом «Выбрать другое».

### Камера (опционально, решение — вопрос В10)

Запись «реакции» прямо в приложении (фронтальная камера, пока идёт предпросмотр симуляции) — сильный сценарий для формата «реакция». В 1.0 по умолчанию **не входит**: пользователь снимает себя системной камерой и импортирует. Включение в 1.0 добавит разрешения камеры/микрофона и ~2 недели работ.

## 3.3. Раскладки split-screen (Требование 6)

Холст кадра — 9:16 (1080×1920 при экспорте 1080p, 720×1280 при 720p). Слоты: **S** — симуляция, **V** — видео пользователя.

| Код | Раскладка | Описание | Регулировки |
|---|---|---|---|
| `L1` | **Сверху / снизу** (по умолч.) | S сверху, V снизу | Пропорция 30–70% (шаг 1%, «магниты» на 33/50/67%), кнопка «поменять местами» (= `L1'`, V сверху) |
| `L2` | **Слева / справа** | Две вертикальные полосы | Пропорция 30–70%, «поменять местами» |
| `L3` | **Картинка в картинке** | S на весь кадр, V в плавающем окне (или наоборот) | Форма окна (скруглённый прямоугольник / круг), размер 20–60% ширины, положение перетаскиванием с «магнитами» к углам вне зон интерфейса площадок, рамка, тень |
| `L4` | **Только симуляция** | S на весь кадр | — |
| `L5` | **Только видео + мини-симуляция** | V на весь кадр, S в окне (формат «я смотрю, как шар…») | как L3 |

### Регулировки внутри слота

- **Заполнение:** `Cover` (обрезать по краям, по умолч.) или `Fit` (вписать с полями).
- **Панорама и масштаб:** жестами (перетаскивание, щипок) прямо в предпросмотре; двойной тап — сброс.
- **Поворот** видео пользователя с шагом 90°, зеркало по горизонтали (для фронтальной камеры).
- **Фон полей** (`Fit`): цвет, размытое это же видео, цвет темы.
- **Разделитель** (L1/L2): толщина 0–16 px, цвет, «стеклянный» разделитель (§4.5), скругление углов слотов 0–48 px, внешние отступы 0–48 px.

### Подсказки площадок

Переключатель **«Зоны интерфейса»** накладывает полупрозрачные маски зон, которые перекрывает интерфейс TikTok, Reels и Shorts (подпись, кнопки справа, нижняя панель). Маски — данные в JSON, обновляются через Remote Config, когда площадки меняют интерфейс. При экспорте маски не рисуются.

### Приёмка

- Смена раскладки и пропорции применяется в предпросмотре за ≤ 1 кадр (без перекомпоновки видео).
- Все 5 раскладок × 2 варианта «поменять местами» × 2 разрешения дают в экспорте ровно то же, что в предпросмотре (визуальное сравнение кадров с допуском SSIM ≥ 0,98, §8.5).

## 3.4. Таймлайн, обрезка и синхронизация

Таймлайн 1.0 — **две дорожки** (S и V) плюс дорожка текста и аудиодорожка музыки (опционально). Это сознательное ограничение (столп С2).

| Функция | Описание |
|---|---|
| Обрезка клипа S | Ручки начала и конца на дорожке S; превью кадров-миниатюр |
| Обрезка видео V | То же; миниатюры извлекаются в фоне |
| Сдвиг V относительно S | Перетаскивание дорожки V; точная подстройка ±1 кадр кнопками |
| Длительность ролика | `Авто` (= длина S после обрезки), `= V`, или вручную; не более 180 с |
| Если S короче ролика | Стоп-кадр / замедленный повтор финала / цикл / «досимуляция» (продолжить физику после финала) |
| Если V короче ролика | Стоп-кадр / цикл / чёрный слот / растянуть S на весь кадр |
| Скорость S | 0,5×–2× для всего клипа (меняет частоту выборки тиков, физика та же) |
| Слоу-мо финала | Последние 1–3 с клипа S в 0,25–0,5× (часто используется вместе с «Финал: замедление») |
| Обложка | Выбор кадра-обложки (для галереи и для некоторых площадок, которые берут первый кадр) — в 1.0 обложкой становится первый кадр ролика, переключатель «Поставить выбранный кадр первым на 0,1 с» |
| Отмена / повтор | 50 шагов, на уровне проекта |

## 3.5. Текст и надписи

- До **5 текстовых слоёв** на ролик.
- **Шаблоны:** «Какой шар победит?», «Пиши свой цвет в комментариях 👇», «Часть 2», «Попробуй не залипнуть», «Кто выживет?», счётчик «Осталось: N» (живой, связан с HUD симуляции), таймер. Тексты шаблонов локализованы.
- **Стили:** 8 шрифтов (лицензия OFL, включая кириллицу), заливка, обводка 0–8 px, тень, плашка (сплошная / «стекло»), выравнивание, размер 12–160 px.
- **Время появления и исчезновения** на таймлайне; анимации входа (появление, выезд, «печатная машинка», «подпрыгивание»).
- **Эмодзи:** поддерживаются цветные эмодзи. Для одинакового вида на iOS и Android используется встроенный набор (Noto Color Emoji или Twemoji — открытые лицензии), а не системные шрифты.
- Текст рисуется в компоновщике студии (§7.5), а не системой, поэтому выглядит одинаково в предпросмотре и экспорте.

## 3.6. Звук

| Дорожка | Источник | Регулировки |
|---|---|---|
| Звуки симуляции | Офлайн-рендер событий реплея тем же микшером (§2.7, §7.8) | Громкость 0–200%, смена звукового пакета прямо в студии (пересчитывается из событий, симуляцию перезапускать не нужно) |
| Звук видео пользователя | Аудиодорожка импортированного файла | Громкость 0–200%, выключение |
| Музыка (опц.) | Встроенная библиотека фоновых треков (8–12 royalty-free треков, собственные или с лицензией на коммерческое использование) | Громкость, начало, fade in/out 0–2 с |

- Итоговый микс нормализуется к −14 LUFS (типичная громкость коротких видео) с лимитером −1 dBTP, чтобы звуки симуляции не «хрипели» при сотнях ударов.
- Автоприглушение (ducking): при включённой музыке звуки симуляции не глушатся, а голос пользователя — опционально приглушает музыку («Голос важнее», по умолчанию вкл).
- Импорт пользовательской музыки из файлов в 1.0 **не входит** (права и библиотека Apple Music недоступна для экспорта). Пользователь добавляет трендовый звук уже в TikTok — это и так стандартная практика.

## 3.7. Предпросмотр (Требование 7)

- Предпросмотр занимает верхние ~60% экрана студии и всегда показывает итоговый кадр 9:16.
- Воспроизведение в реальном времени: симуляция рендерится из реплея, видео пользователя декодируется системным плеером в текстуру, текст и эффекты накладываются компоновщиком.
- Скраббинг по таймлайну: кадр обновляется ≤ 100 мс (для S — перемотка потока рендера по опорным кадрам, §7.4).
- Переключатель **«Полноэкранный предпросмотр»** показывает ролик на весь экран, как в ленте, с наложением «Зон интерфейса» (опционально).
- Если устройство не успевает воспроизводить предпросмотр 60 FPS (тир C, 1080p60), предпросмотр понижает внутреннее разрешение, а не FPS. На итоговый файл это не влияет.
- Допустимое расхождение звука и изображения в предпросмотре — до 1 кадра (16–33 мс); в экспорте — 0 (кадры и звук ставятся по общим меткам времени).

## 3.8. Экспорт (Требования 8, 9)

### Параметры файла

| Параметр | Значение |
|---|---|
| Контейнер | MP4 (ISO BMFF), индекс `moov` в начале файла (быстрая загрузка на площадки) |
| Видео | H.264 High Profile, уровень 4.2, аппаратный кодер; 8 бит, 4:2:0, BT.709, SDR, full/limited range — limited |
| Разрешения | **720×1280** и **1080×1920** (9:16). Ландшафт и 1:1 — версия 1.1 |
| Частота кадров | **30** или **60** FPS, постоянная (CFR) |
| Битрейт (VBR, цель) | 1080p60 — 16 Мбит/с; 1080p30 — 10 Мбит/с; 720p60 — 10 Мбит/с; 720p30 — 6 Мбит/с. Ключевой кадр каждые 2 с |
| Аудио | AAC-LC, 48 кГц, стерео, 192 кбит/с |
| Длительность | 1–180 с |
| Метаданные | Название проекта, дата; без геолокации и персональных данных |
| HEVC | версия 1.1 (меньше размер, но не все площадки и старые Android-устройства одинаково хорошо принимают HEVC) |

Почему такие битрейты: площадки всё равно перекодируют загрузку; запас качества на входе уменьшает артефакты перекодирования на мелких быстрых объектах (сотни шаров — худший случай для кодеков). Значения вынесены в Remote Config.

### Поток экспорта (пользователь)

1. Кнопка **«Экспорт»** в студии → лист настроек: разрешение (по умолч. 1080p), FPS (по умолч. 60 на тирах A/B, 30 на тире C), водяной знак (§3.10), оценка размера файла и времени экспорта.
2. **Rewarded-шлюз** (если нет права `NO_EXPORT_ADS`: Remove Export Ads, No Ads, позже Ultimate), §5.3.1.
3. **Прогресс экспорта:** полноэкранный «стеклянный» лист с превью текущего кадра, процентом, оставшимся временем, кнопкой «Отмена». Экран не гаснет (`isIdleTimerDisabled` / `FLAG_KEEP_SCREEN_ON`).
4. **Готово:** превью ролика, кнопки «Сохранить в галерею» (по умолчанию сохраняется автоматически, настройка), «Поделиться» (системный лист), «TikTok», «Instagram», «YouTube» (в 1.0 открывают системный лист с подсказкой; прямая публикация — 1.1), «Новый ролик», «В проекты».

### Сохранение в галерею

- iOS: `PHPhotoLibrary` с правом **только на добавление** (`NSPhotoLibraryAddUsageDescription`), альбом «Ballverse».
- Android 10+: `MediaStore` без разрешений, папка `Movies/Ballverse`. Android 9: разрешение `WRITE_EXTERNAL_STORAGE` (только для API ≤ 28).

### Прерывания и надёжность

| Ситуация | Поведение |
|---|---|
| Приложение ушло в фон (звонок, переключение) | Экспорт ставится на паузу на границе сегмента; по возвращении продолжается. iOS не даёт рисовать на GPU в фоне, поэтому фонового экспорта нет |
| Приложение выгружено системой | Экспорт сегментный (сегменты по 2 с, §7.5): при следующем запуске предлагается «Продолжить экспорт» с последнего готового сегмента. **Релиз 1:** допускается экспорт одним файлом — тогда при уходе в фон или выгрузке экспорт отменяется, временный файл удаляется, повторный экспорт идёт без новой рекламы (RW4) |
| Мало места | Перед стартом проверяется свободное место ≥ 2 × оценка размера + 200 МБ; иначе понятное сообщение и ссылка на «Хранилище» (§3.9) |
| Перегрев | При `thermalState = serious` (iOS) / `THERMAL_STATUS_SEVERE` (Android) экспорт замедляется (пауза между сегментами), пользователь видит подсказку. Качество не снижается |
| Ошибка кодера | Одна автоматическая повторная попытка сегмента; затем вариант «Экспорт в 720p/30» и отправка отчёта в Crashlytics |
| Отмена пользователем | Временные файлы удаляются немедленно; rewarded-просмотр «сгорает» (повторный экспорт снова через шлюз). Вопрос В5: засчитывать ли просмотр на повторную попытку в течение 10 минут — по умолчанию **да**, чтобы не наказывать пользователя за сбой |

### Скорость экспорта (целевые значения, ролик 30 с)

| Тир | 720p30 | 1080p30 | 1080p60 |
|---|---|---|---|
| A | ≤ 10 с | ≤ 15 с | ≤ 30 с |
| B | ≤ 20 с | ≤ 30 с | ≤ 60 с |
| C | ≤ 40 с | ≤ 75 с | ≤ 150 с |

Для режимов с большим числом тел (M09, M15) допускается ×1,5 к этим значениям. Проверяется на эталонных устройствах (§8.1).

### Приёмка (Требования 8, 9)

- Файл открывается и проигрывается системными плеерами iOS и Android, загружается в TikTok, YouTube Shorts и Instagram Reels без перекодирования на стороне клиента площадки (проверка вручную на каждом релизе).
- `ffprobe` на эталонных роликах: 1080×1920 или 720×1280, CFR 30/60, H.264 High, AAC 48 кГц, длительность = длительность проекта ± 1 кадр.
- Ни одного пропущенного или повторного кадра (проверка по кадровому счётчику, отрисованному в тестовой сборке).

## 3.9. Проекты и хранилище (Требование 10)

### Что такое проект

Проект = клип (реплей + обрезка) + видео пользователя (копия файла) + настройки студии (раскладка, текст, звук, длительность) + история экспортов.

- **Автосохранение** после каждого изменения (с задержкой 1 с) и при уходе приложения в фон.
- **Список проектов:** сетка карточек с обложкой, длительностью, датой изменения, значком режима. Действия: открыть, дублировать, переименовать, удалить, «Экспортировать снова».
- **Повторный экспорт** проекта в другом разрешении/FPS без повторной симуляции — главный выигрыш модели реплеев.
- **Библиотека клипов** — отдельная вкладка в «Проектах»: сохранённые клипы без студии.
- **Настройки** (общие и последние параметры каждого режима, свои пресеты) хранятся отдельно от проектов и не удаляются вместе с ними.

### Совместимость проектов между версиями

- Файл проекта содержит `schemaVersion`; при обновлении приложения выполняется миграция (§7.4).
- Реплей содержит `simVersion` режима. Если обновление изменило физику режима и реплей нельзя воспроизвести детерминированно, используется сохранённый поток рендера (§7.4). Если и его нет — проект открывается с предупреждением «Симуляция будет пересчитана, результат может отличаться» и вариантами «Пересчитать» / «Оставить как есть (только уже экспортированные видео)».

### Хранилище

- Экран **«Хранилище»** в настройках: сколько занимают проекты, клипы, видео пользователей, кэш миниатюр; очистка кэша; удаление старых проектов.
- Предупреждение при занятом месте > 2 ГБ.
- Временные файлы экспорта удаляются после успеха или отмены и при старте приложения.
- iOS: папка проектов попадает в резервную копию iCloud устройства, кэш и временные файлы — нет (`isExcludedFromBackup`). Android: Auto Backup включает только настройки и пресеты (видео слишком велики для лимита 25 МБ).

## 3.10. Водяной знак (Р13)

Водяной знак «Made with Ballverse» — бесплатный канал органического роста: каждый опубликованный ролик показывает зрителям, где он сделан. По решению владельца (Р13) знак стоит на всех экспортах, а убирается **только правом `NO_WATERMARK`**. Это право дают No Ads Bundle или обе покупки отключения рекламы (Р21, в том числе в релизе 1), а после первого релиза — также Ultimate Bundle (§5.0.2).

### Внешний вид

- Логотип (светящийся шар) и надпись «Ballverse», белые, непрозрачность 70%, лёгкая тень для читаемости на светлом фоне. Высота — 2,5% высоты кадра (48 px в 1080p, 32 px в 720p).
- Положение: левый верхний угол, внутри безопасной зоны, вне масок интерфейса TikTok, Reels и Shorts (§3.3). Если в этом месте стоит окно PiP или текстовый слой, знак автоматически переезжает в правый верхний угол. Пользователь не может перемещать, масштабировать или перекрывать знак.
- В последние 1,5 с ролика знак не увеличивается и не превращается в заставку: финал ролика принадлежит автору. Отдельной концевой заставки нет.
- Знак рисует компоновщик (§7.5), поэтому он виден и в предпросмотре: пользователь заранее видит итоговый кадр.

### Поведение

| У пользователя | Предпросмотр и экспорт | Лист экспорта |
|---|---|---|
| нет `NO_WATERMARK` | знак есть | Строка «Водяной знак» с замком; тап открывает лист No Ads или недостающей покупки рекламы (§5.0.3; после релиза — также Ultimate, §5.2). Экспорт со знаком не блокируется |
| есть `NO_WATERMARK` | по переключателю, по умолчанию **без знака** | Переключатель «Водяной знак»: кто хочет знак, может его оставить |

- Право проверяется в момент экспорта. Если покупку вернули (§5.4), следующие экспорты снова идут со знаком. Уже сохранённые файлы не меняются.
- Повторный экспорт старого проекта после получения права (No Ads, позже Ultimate) идёт без знака: знак не «запекается» в проект.
- Аварийный выключатель `watermark_enabled` в Remote Config (§9.3) убирает знак у всех без обновления приложения.
